## Architecture Overview
#### Describe your approach here. Keep it short and clear.

- We extract features using Short-Time Fourier Transform via librosa to generate a spectrogram for each song. Dominant frequency peaks are identified using a constellation map approach with a 2D maximum filter. Each peak is paired combinatorially with neighbouring peaks using time deltas to generate 20-character SHA1 fingerprint hashes. These hashes are stored in a SQLite database with a dedicated index on the hash column, enabling O(1) lookup. All 1,000 songs in the GTZAN dataset were preprocessed offline in a single indexing pass, producing approximately 950,000 fingerprint entries in total.

- We use Shazam-style landmark fingerprinting for query matching. The incoming audio snippet undergoes the same peak extraction and hash generation pipeline as the indexed songs. Each query hash is looked up in the SQLite index and candidate songs accumulate votes per hash collision. Time-offset alignment is then applied: only votes where the difference between the database offset and the query offset is consistent across multiple hashes are counted. The song with the highest temporally aligned vote count is returned as the best match. The system also returns the top 3 candidates with individual confidence scores, computed as matched hashes divided by total query hashes.

- The backend is built with FastAPI, which provides native async support allowing multiple concurrent queries to be processed without blocking. The SQLite hash index scales efficiently because lookup complexity is O(1) per hash regardless of dataset size. The fingerprint database is precomputed entirely offline, so runtime query latency is independent of the dataset size. For production scale beyond thousands of songs, the SQLite backend can be swapped for Redis or a distributed key-value store with no changes to the matching logic.

- Log-scaled spectrograms and peak-based hashing are inherently robust to noise and distortion because dominant frequency peaks persist even under significant audio corruption. The system was validated with artificially noisy audio clips generated by adding Gaussian noise, achieving correct identification at 43% confidence under heavy noise conditions. A confidence threshold filters false positives, returning no match when the score is too low rather than returning a wrong result. For short 5 to 10 second clips the end-to-end query latency is under 500 milliseconds.
